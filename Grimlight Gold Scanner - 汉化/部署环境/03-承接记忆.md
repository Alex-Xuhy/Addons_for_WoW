## 4. 已核实的事实（不要重查）

完整版见 [02-技术情报.md](02-技术情报.md)。三条最要紧的：

1. **`## Interface: 16001`**，**`## AllowLoadGameType: camelot`**（无限的游戏类型代号是 camelot）。客户端基于 **Mainline 代码库**，12.0 的 API（Housing、Mythic+）都在，只是被 camelot 规则关掉
2. **看不到其他玩家的当前金币。** `GetMoney()` 只对自己。他人的**历史最大金币**走成就统计对比：`SetAchievementComparisonUnit` + `GetComparisonStatistic`
3. **机密值闸门真实存在且已启用。** `ShouldUnitComparisonBeSecret(unit1, unit2)`；配套 `C_Secrets` 体系；GGS 用 `GGS.IsSecret()` 把每次读取都包起来

**另一条必须知道的（2026-10-11 追加）**：这条数据链路**已经引起政策争议**。有人正式请求暴雪审查"历史最大金币、累计获得金币是否应该通过对比 API 暴露给插件收集他人数据"，依据是暴雪插件政策"addons must not negatively affect the game for other players"。同时暴雪正在严打 RMT。**这是项目最大的外部风险，详见 [04-先例与政策风险.md](04-先例与政策风险.md)。**

**★ 第四条（2026-10-12 实机追加，最重要的一条）**：**国服的统计量数据是残缺的，而且残缺方式很反直觉。**

| 视角 | 结果 |
|---|---|
| 读**自己**（`GetStatistic`） | **83 个 key 全部返回 `"--"`**，一个值都读不到 |
| 读**别人**（`GetComparisonStatistic`） | 本客户端 196 条统计量里，**只有 14 个 ID 有值**；两个玩家的可读集合完全相同 |
| 机密值 | **0 例**——返回的是普通字符串 `"--"`，不是被隐藏的机密值 |

**推论**：不是客户端藏了数（否则是机密值），也不可能是本地化问题（83/83 绑定成功）——
**是服务器没给数**。⚠️ 这**不等于**「国服独有」：我们没有国际服的观测，只能说**这是服务端行为**，
已请作者在他那边跑同一行命令对照（见 `07-给原作者的回复-初稿.md`）。

配套的三个数字要记住：**196**（统计量总数）、**83**（key 数，全部绑定成功）、**14**（对比读取真正有值的 ID 数）。
另有 `919`（拍卖行所得金币）**从未上报过**，而它进了 GGS 的 `complete` 判据 → **判定恒为 THIN「数据太少」**。

完整证据见 [02-技术情报.md](02-技术情报.md) **第 11 节**。

## 6. 我犯过的一个错，记录下来

我最初主张「**不要印结论，只展示原始数据**」。但 GGS 的成熟做法是印结论（一致性评分 + 四档判定），同时把全部输入、每条理由、以及三遍 `Unexplained is not proof of RMT` 的免责声明都给出来。

**修正后的判断**：关键不在印不印结论，在**给什么下结论**——给「数字」下结论可以，给「人」下结论不行。

用户接受了这个修正。**不要在新会话里退回到我最初的绝对说法。**
